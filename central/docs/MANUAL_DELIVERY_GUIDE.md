# راهنمای ساخت و تحویل دستی APK — پنل مدیریت (ساده‌شده v3)

**مسیر:** `https://your-host.example.com/admin/delivery_builder.php` (منو: ساخت دستی)

## چرا دستی؟
وقتی مشتری اولین بار از ربات فروش ثبت‌نام نکرده یا می‌خواهید بدون چرخه کیف‌پول/سفارش، مستقیم بسته بسازید — این صفحه همه مراحل را در یک فرم 2 فیلدی انجام می‌دهد.

## پیش‌نیاز
1. یک فایل APK عمومی در `APK → آپلود APK` بارگذاری و فعال کرده باشید.
2. توکن ربات مشتری را از @BotFather گرفته باشید (مثال: `123456789:AAH...`).

## مراحل — فقط 2 فیلد

### 1) نام کاربری مشتری + توکن ربات
- **نام کاربری (username)** — فیلد اول `مشتری (نام کاربری یکتا)` — 3 تا 32 کاراکتر `a-zA-Z0-9_-` (و حروف فارسی). اگر مشتری با این نام وجود دارد استفاده می‌شود، اگر نه ساخته می‌شود (بدون ایمیل/رمز). نام یکتاست — تکراری خطا `نام کاربری تکراری است`.
- **توکن ربات** — فیلد دوم `توکن ربات تلگرام`، جهت LTR.
- سیستم هنگام `ساخت بسته تحویل`، خودکار `https://api.telegram.org/bot<TOKEN>/getMe` را صدا می‌زند:
  - اگر `ok:true` → نام ربات `@username` و `id` نمایش داده می‌شود و ادامه می‌دهد.
  - اگر نامعتبر → خطا و عدم ذخیره.

**امنیت:** توکن فقط در این درخواست POST می‌آید، با `AES-256-GCM` رمزنگاری و در `telegram_bots` + فایل `private/telegram_tokens/<customer_id>.enc` (0600) ذخیره می‌شود. هرگز در APK، لاگ یا لینک plaintext نمی‌ماند.

### 2) انتخاب APK
- کشوی `فایل APK عمومی` — نسخه فعال پیش‌فرض `selected` است. هر سطر: نسخه، versionCode، نام فایل، حجم، فعال.
- اگر خالی است → به `APK → آپلود` بروید.

### 3) ساخت
- دکمه `🔨 ساخت بسته تحویل` → سرور:
  1. نام کاربری را validate (`is_valid_username` 3-32 یکتا) — اگر تکراری → خطا.
  2. توکن را validate و `getMe` (curl) — اگر نامعتبر → خطا.
  3. اگر مشتری جدید است → `create_customer_by_username` → `customers(name, uuid, email NULL, password_hash NULL, status ACTIVE)` + `wallets` + `api_keys`. اگر موجود است → همان `customer_id` استفاده می‌شود.
  4. توکن را `encrypt_token` → `telegram_bots(customer_id, bot_token_enc, bot_username, bot_id, is_connected=1)` + فایل `.enc` 0600.
  5. APK را چک (وجود فایل روی دیسک `private/apk/`).
  6. یک سفارش `orders(product_code=manual_delivery, amount=0, status=delivered)` می‌سازد (برای حسابرسی).
  7. `create_apk_delivery(customer_id, apk_id, order_id)` → `delivery_token 64hex` + `api_key 64hex` + `expires_at = NOW+30days` + ردیف `api_keys` جدید.
  8. همه را در یک تراکنش کامیت و `admin_logs manual_delivery_created` ثبت.

### 4) نتیجه
کارت سبز:
- لینک دانلود اختصاصی: `https://HOST/api/delivery.php?t=<token>`
- API Key اختصاصی: `64hex`
- دکمه `📥 دانلود APK` (مستقیم) + `📤 ارسال از طریق ربات فروش` (اگر مشتری `telegram_id` دارد و `SALES_BOT_TOKEN` تنظیم است → `sendDocument` با کپشن لینک+کلید).

می‌توانید لینک/فایل را کپی و دستی برای مشتری بفرستید.

## نکته شفاف درباره کامپایل مجدد

> **APK عمومی است، نیازی به کامپایل مجدد نیست.**
> تنظیمات و دسترسی هر مشتری (delivery_token, api_key, bot mapping) کاملاً در سرور نگهداری می‌شود. APK در اجرا با `X-API-Key` خود (که در تحویل به مشتری داده می‌شود) به `api/config.php` و `api/telegram.php` وصل می‌شود.
> اگر در آینده بخواهید کلید داخل باینری Bake شود (مثلاً `assets/config.json` داخل APK)، نیاز به `apktool d → ویرایش → apktool b → jarsigner` است که امنیت را کاهش می‌دهد (کلید داخل APK قابل استخراج) و توصیه نمی‌شود. بنابراین روش فعلی (سرورمحور) امن‌تر و صحیح است و فایل صوری ساخته نمی‌شود.

## مدیریت دسترسی تحویل‌ها (همین صفحه، جدول پایین)

| ستون | معنی |
|---|---|
| لینک | `delivery.php?t=...` (کلیک = دانلود) |
| کلید | `api_key` (مخفف 12کاراکتر) |
| دانلود | تعداد |
| انقضا | `expires_at` — `لغو لینک` → `expires_at = دیروز` + `api_keys.is_active=0` → 410/403 |
| عملیات | `لغو لینک` / `صدور مجدد` (توکن و کلید جدید + کلید قدیمی غیرفعال + لاگ) |

هم‌چنین در `مدیریت دسترسی کلی` لینک به صفحات `customers.php` (ACTIVE/SUSPENDED/DISABLED), `bots.php` (قطع), `devices.php` (مسدود) داده شده — همه در سرور اعمال و APK 403 می‌گیرد.

## خطاها
- `نام کاربری نامعتبر` → فقط 3-32 کاراکتر a-z0-9_- (فارسی مجاز)، تکراری نباشد.
- `نام کاربری تکراری است` → نام دیگری انتخاب کنید یا همان مشتری را از کشو استفاده کنید (در فرم ساده جدید، کشو حذف شده و سیستم خودکار تشخیص می‌دهد — اگر نام موجود باشد از همان استفاده، اما اگر هم‌زمان با توکن جدید بسازید، رکورد موجود به‌روزرسانی می‌شود؛ در صورت تضاد لاگ می‌دهد).
- `توکن نامعتبر` → @BotFather را چک کنید.
- `فایل APK روی سرور موجود نیست` → مسیر `private/apk/` را چک کنید (پرمیژن 750).
- `مشتری telegram_id ندارد` برای ارسال ربات → لینک را دستی بفرستید یا مشتری را از طریق ربات فروش ثبت‌نام کنید (`/start`).

## مهاجرت از نسخه قبلی (v2 → v3)
- `migration_v3_simplify_customer.sql` را بعد از `migration_v2` اجرا کنید: `email` و `password_hash` به `NULL` تبدیل، `UNIQUE(name)` اضافه، نام‌های خالی به `user_<id>` تبدیل — اطلاعات قبلی (مخصوصاً `admin@local`) حفظ می‌شود.
- از این پس ساخت مشتری در پنل و API فقط با `name` (نام کاربری) — ایمیل اختیاری و nullable است.

## لاگ
هر ساخت/ارسال/لغو/صدور در `admin_logs` + `security_events` + `private/logs/security.log` ثبت می‌شود.
